# 系統架構設計文件

本文件說明各項設計決策的「為什麼」。目標讀者：要把這份專案讀懂、
改造、移植的嵌入式工程師。

## 1. 分層架構

```
┌─────────────────────────────────────────────────────────┐
│  app/    應用層：任務、業務邏輯、CLI 命令、UI 頁面        │
│          （task_imu / task_btn / task_ui / task_comm…） │
├─────────────────────────────────────────────────────────┤
│  mw/     中介層：與硬體無關的可重用元件                   │
│          sched / proto / storage / button / ringbuf /   │
│          crc16 / cli / xutil                            │
├─────────────────────────────────────────────────────────┤
│  drivers/ 裝置驅動：認得「晶片」但不認得「板子」          │
│          mpu6050 / at24cxx / ssd1306 / gfx / imu(介面)  │
├─────────────────────────────────────────────────────────┤
│  bsp/    板級支援：唯一允許出現腳位與 HAL handle 的地方   │
│          bsp_board.h(腳位表) / bsp_uart / bsp_i2c / wdg  │
├─────────────────────────────────────────────────────────┤
│  HAL / CMSIS（CubeMX 產生）                              │
└─────────────────────────────────────────────────────────┘
```

**依賴規則：只能往下依賴，不能往上、不能跳層亂抓。**
- `drivers/` 透過 `bsp_i2c.h` 存取匯流排，不碰 `hi2c1`。
- `mw/` 完全不含硬體相依 → 可直接在 PC 上單元測試（`tests/host/`）。
- 換板子（改腳位）只動 `bsp_board.h` + CubeMX；換 MCU 系列重寫 `bsp/`
  即可，`drivers/ mw/ app/` 原封不動 —— 這就是可移植性的具體含義。

例外說明：`imu` 介面放在 `drivers/`，因為它抽象的是「感測後端」
（Mahony 軟體解算 vs DMP 硬體解算），兩個實作共用同一介面由
`APP_USE_MPU_DMP` 在編譯期選擇。

## 2. 併發模型：協作式排程器（無 RTOS）

`mw/sched.c`：靜態任務表 + 週期輪詢，主迴圈單執行緒。

| 任務 | 週期 | 相位 | 職責 |
|---|---|---|---|
| imu | 10ms | 0 | 姿態解算（100Hz）、校正請求 |
| btn | 10ms | 3 | 按鍵掃描 |
| comm_rx | 10ms | 5 | BLE 收包解析、CLI、橋接 |
| comm_tx | 100ms* | 7 | 姿態遙測（*=1000/hz，可動態調整） |
| ui | 100ms | 20 | OLED 渲染、LED 心跳 |
| storage | 250ms | 40 | EEPROM 延遲落盤 |
| sys | 1000ms | 60 | STAT 回報、看門狗總檢查 |

- **相位錯開**：避免每逢整百毫秒所有任務擠在同一輪執行造成尖峰。
- **鐵律：任務不得長時間阻塞。** 排程器對每個任務用 DWT 計時，
  超過週期記一次 overrun（CLI `stat` 可見）—— 違規立刻現形。
  唯一豁免是陀螺儀校正（1 秒阻塞），它在已知路徑內手動餵狗並有文件標注。
- **與 RTOS 的關係**：任務函式是無狀態進入點，換成 FreeRTOS 時
  每個任務包一層 `for(;;){ fn(); vTaskDelay(); }` 即可，上層邏輯不變。

### 為何單執行緒可以不加鎖？

所有任務都在主迴圈序列執行，任務之間存取共享資料天然互斥。
需要小心的只有「ISR ↔ 主迴圈」邊界，全部收斂在兩處：
1. **ring buffer**（SPSC 契約：head 只有生產者寫、tail 只有消費者寫）；
2. **launch/complete 旗標**（`tx_active`、`dma_busy`），以 PRIMASK
   臨界區保護 test-and-set。

## 3. 中斷優先權地圖（NVIC group 4）

| 優先權 | 中斷 | 理由 |
|---|---|---|
| 5 | USART2、DMA1_Ch6 | BLE RX 不能丟資料；同級互不搶佔 → 回呼序列化 |
| 6 | DMA1_Ch7 | BLE TX 完成 |
| 7 | I2C2_EV/ER、DMA1_Ch4 | OLED DMA 完成 |
| 8 | USART1 | 除錯埠 |
| 9 | EXTI9_5 | MPU INT（只做計數） |
| 15 | SysTick | HAL 時基 |

原則：**資料會流失的（RX）最高、完成通知次之、人機介面最低**。

## 4. 資料流

### BLE 接收（不定長封包的標準解法）

```
nRF52832 → USART2 RX → DMA 環形緩衝(256B) ─┐
   IDLE line / 半滿 / 全滿 中斷 ────────────┴→ RxEventCallback
   → 搬進 RX ring(1KB) → task_comm_rx 每 10ms → proto 狀態機 → 命令分派
```

CPU 介入次數 ∝ 封包數而非位元組數；115200bps 滿載也只是每次
IDLE 搬一段記憶體。對照組（每位元組中斷）在相同負載下要進中斷
11520 次/秒。

### OLED 刷新

```
task_ui(100ms) → gfx_* 畫進 framebuffer(1KB)
   → oled_flush() 送第 0 頁：3B 頁命令(阻塞 ~90µs) + 128B DMA
   → 之後每頁由主迴圈的 oled_poll() 在前頁 DMA 完成後接力
   → 8 頁共 ~28ms 背景完成；下一幀若尚未送完就整幀跳過（絕不等待）
```

為什麼用「分頁定址」而不是 SSD1306 的水平定址一次串 1KB？
市售模組實際晶片混雜（SSD1306 / SSD1315 / **SH1106**），SH1106
只支援分頁定址、忽略 0x20/0x21/0x22——用水平串流驅動它會得到
滾動錯位的畫面（常見災情）。分頁定址是各家控制器的交集
（u8g2 等成熟驅動同款作法），代價僅是每幀多 8 次 3-byte 命令。
面板參數（控制器/COM 接線/旋轉）可經 CLI `oled` 命令執行期切換，
現場確認後回填 `app_config.h` 固化。

I2C1（感測）與 I2C2（顯示）分開的原因：26ms 的顯示傳輸若與
100Hz 感測讀取共享匯流排，會直接吃掉 2.6 個取樣週期。
分匯流排 + DMA 後，顯示對感測的干擾為零。

### EEPROM 寫入路徑

```
按鍵事件 → RAM 快取變更 + mark_dirty
   → task_storage(250ms) 檢查：靜止 2s 或持續變更逾 10s
   → 雙槽輪替寫入（詳見下節） → 讀回驗證
```

## 5. 儲存層：雙槽輪替（power-fail safe）

槽格式（32B）：`MAGIC(2) SEQ(2) LEN(1) RSV(1) PAYLOAD(≤24) CRC16(2)`

- 寫入永遠寫「非現役槽」，寫完讀回驗證；現役槽在此期間完好無損。
  → 任何時刻斷電，至少一份完整記錄存活。
- SEQ 單調遞增（u16 環繞，有號差值比較），開機取較新的有效槽。
- LEN 欄位使韌體升級後記錄結構「只增不改」即可自動零擴充遷移。
- 磨耗預算：AT24C02 標稱 100 萬次/cell。延遲落盤讓連續點擊合併成
  一次寫入；雙槽再把磨耗攤半。以每天 100 次落盤估算：
  1,000,000 × 2 / 100 ≈ 54 年。

## 6. 看門狗策略：任務簽到制

- IWDG 由 CubeMX 在周邊初始化尾聲啟動（LSI/64、reload 2500 ≈ 名目 4s；
  LSI 誤差 ±50% → 實際 2.6~8s，餵狗週期 1s 保有裕度）。
- 每個關鍵任務執行時 `bsp_wdg_checkin(bit)`；`task_sys` 每秒檢查
  **全部位元到齊才餵狗**。任何一個任務卡死 → 整機重置，
  開機 banner 與 BOOT 事件都會標注 "IWDG"，遠端可觀測。
- 除錯時 `__HAL_DBGMCU_FREEZE_IWDG()` 讓中斷點不會觸發重置（僅
  除錯器連線時生效，量產不受影響）。
- 已知長阻塞（校正）在迴圈內 `bsp_wdg_feed_raw()`，屬顯式豁免。

## 7. 降級運行（graceful degradation）

開機時每個周邊獨立初始化、獨立標記健康狀態：

| 故障 | 系統行為 |
|---|---|
| MPU6050 離線 | UI 顯示 IMU FAIL、遙測角度凍結、LED 快閃；執行期連續讀取失敗會自動重新初始化 |
| EEPROM 離線 | 以預設參數運行、停用落盤、STAT 回報 bit2=0 |
| OLED 離線 | 跳過渲染，LED/CLI/BLE 照常 |
| BLE 模組拔除 | 僅遙測無人接收；TX ring 滿→丟棄計數（不阻塞） |
| I2C 匯流排卡死 | 連續錯誤 3 次自動 9-clock bus recovery |

## 8. 記憶體預算（F103C8：64KB flash / 20KB RAM）

主要靜態 RAM 佔用：

| 項目 | 大小 |
|---|---|
| OLED framebuffer | 1024B |
| BLE RX ring + DMA 緩衝 | 1024 + 256B |
| BLE TX / DBG TX / DBG RX ring | 512+512+256B |
| 任務表、解析器、記錄快取等 | <1KB |
| 主堆疊（CubeMX 設 0x800） | 2KB |

合計約 7KB，餘裕充足。**全專案零 `malloc`**：所有緩衝靜態配置，
無碎片化、無 OOM 路徑，行為可在連結期完全確定。

Flash 方面：務必以 `-Os`（或 ≥`-O1`）建置；`-O0` 下 HAL 展開
可能逼近 64KB 上限（啟用 DMP 時尤甚）。printf 禁用 `%f`
（角度以 ×100 定點整數流通）避免連入浮點格式化庫。

## 9. 已知限制與延伸方向

- **Yaw 漂移**：六軸（無磁力計）物理上無絕對航向，Mahony 與 DMP
  皆然。延伸：I2C1 掛 HMC5883L/QMC5883 做九軸融合。
- **BLE 鏈路狀態未知**：透傳模組未接 STATE 腳，韌體無法得知
  是否有人連線。延伸：接模組 STATE 腳到 GPIO，或啟用模組的
  連線事件 AT 回報。
- **時間戳**：遙測用 uptime 而非絕對時間。延伸：主機下發
  對時命令 + RTC。
- 更多練習題見 README「教學單元」。
