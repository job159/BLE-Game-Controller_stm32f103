# OLED 畫面看懂指南（新手版）

這份文件把裝置那塊 128×64 小螢幕上**每一個數字、每一個縮寫**都解釋清楚，
給第一次接觸這個裝置的人看。看完你就能不接電腦、光看螢幕就知道系統健不健康。

> 螢幕上的字都是英文縮寫（這是刻意的——序列埠/顯示的編碼相容性最好）。
> 這份文件用中文告訴你每個縮寫是什麼、正常長什麼樣、不對勁時代表什麼。

---

## 0. 先學會操作

- **KEY1（PA1）單擊 = 換頁**。開機先看到開機畫面，之後在幾個頁面之間循環切換。
- 螢幕最上面一行通常是**頁面標題**（例如 `EEPROM`、`BLE LINK`、`SYSTEM`），
  底下一條橫線，線下才是內容。
- 畫面偶爾底部會跳出一條**提示框**（例如 `CAL OK`），那是「剛剛發生了什麼事」
  的即時通知，1.5 秒後自己消失，不是固定內容。

頁面順序（KEY1 一直按會這樣循環）：

```
開機畫面 →（1.5秒後自動進入）→ 儀表板 → EEPROM → BLE鏈路 → 原始值 → 系統 →（回到儀表板）
  SPLASH                         DASH      STOR      COMM      RAW       SYS
```

## 1. 開機畫面（SPLASH）

```
        IMU-BLE
     STM32F103 Node
        v1.1.0
```

| 顯示 | 意思 |
|---|---|
| `IMU-BLE` | 產品名稱 |
| `STM32F103 Node` | 用哪顆晶片 |
| `v1.1.0` | **韌體版本**——燒錄新程式後最該看的一行,確認板子跑的是不是最新版 |

開機約 1.5 秒後自動跳到儀表板。若你剛做過 BLE 鮑率自動佈建,這時可能會閃過一條
提示框 `BLE 9600>115200`,代表模組鮑率被自動改好了(見第 6 節)。

## 2. 儀表板（DASH）— 平常主要看這頁

```
CLK 42       AIR      TX 10Hz
──────────────────────────────
R      -12.34
P       +5.67
Y      +179.9
```

**頂列（三個東西擠在一行）：**

| 顯示 | 全稱 | 意思 | 說明 |
|---|---|---|---|
| `CLK 42` | Click | KEY0 累計**點擊次數** | 這個數字存在 EEPROM,斷電也記得 |
| `AIR` | Air Mouse | **空中滑鼠模式開著** | 只有開啟時才出現;沒看到就是關的。KEY0 雙擊切換 |
| `TX 10Hz` | Telemetry | **姿態資料每秒送幾次**給電腦 | `TX off` = 沒在送。BLE 那頁的 TELEM 是同一個值 |

**三行大字（姿態角度,單位都是「度」）：**

| 顯示 | 全稱 | 意思 | 範圍 |
|---|---|---|---|
| `R` | Roll | **橫滾**——左右翻轉的角度 | -180 ~ +180 |
| `P` | Pitch | **俯仰**——前後點頭的角度 | -90 ~ +90 |
| `Y` | Yaw | **偏航**——水平轉向的角度 | -180 ~ +180 |

把裝置拿起來轉,這三個數字會即時跟著變。這就是 MPU6050 算出來的姿態。

> **注意 Yaw 會慢慢自己漂移**——這不是壞掉。因為沒有磁力計(電子羅盤),
> 偏航方向沒有絕對參考,只能相對測量。這是硬體限制,DMP 模式也一樣。

**若這頁出現 `IMU FAIL`(大字):** 代表 MPU6050 沒連上。檢查 PB6/PB7 接線和
3.3V 供電,再去「系統」頁看 `IMU-` 確認。

## 3. EEPROM 頁（STOR）— 看「記憶」有沒有正常

這頁把存在 AT24 記憶體晶片裡的資料攤開給你看。

```
EEPROM              0x50 4096B
──────────────────────────────
CLK 42*  BOOT 17
HZ 10  FLG 01  SEQ 23
BIAS -12 3 -45
SLOT B  W 5  F 0
```

**標題列右邊:**

| 顯示 | 意思 |
|---|---|
| `0x50 4096B` | 記憶體晶片的**位址(0x50)**與**容量(4096 位元組)**。韌體開機自動偵測 |
| `OFFLINE` | 記憶體**沒連上**——查接線和供電;此時所有「記憶」功能失效 |

**內容:**

| 顯示 | 全稱 | 意思 |
|---|---|---|
| `CLK 42` | Click count | 點擊次數(和儀表板同一個) |
| `*`（跟在 CLK 後面） | dirty | **有變更還沒存進晶片**——按一下 KEY0 會出現,約 2 秒後自動存檔、`*` 消失。這顆星星讓你「親眼看到」延遲存檔機制 |
| `BOOT 17` | Boot count | **開機次數**——每次上電 +1,存在晶片裡 |
| `HZ 10` | telemetry Hz | 遙測頻率(存檔值) |
| `FLG 01` | Flags | **旗標**(16進位):bit0=陀螺儀已校正、bit1=BLE模組已佈建。`01`=只有校正、`03`=兩者都有 |
| `SEQ 23` | Sequence | **記錄序號**——每存一次 +1,用來判斷 A/B 兩份哪份較新 |
| `BIAS -12 3 -45` | Gyro bias | **陀螺儀零偏**(三軸)——校正時量到的靜止誤差,用來扣掉漂移 |
| `SLOT B` | Slot | 目前有效記錄放在 **A 槽還是 B 槽**——每次存檔會輪流換槽(斷電保護設計) |
| `W 5` | Writes | **成功寫入次數** |
| `F 0` | Fails | **寫入失敗次數**——正常應該是 0;一直增加代表晶片有問題 |

**新手常見疑問:「為什麼我按 KEY0 但重開機數字不見了?」**
→ 按完要**等 `*` 消失**(約 2 秒,存檔完成)再斷電。按完立刻拔電,那幾下還在 RAM
裡沒進晶片,當然不見。這是防止 EEPROM 太快磨損的刻意設計。

## 4. BLE 鏈路頁（COMM）— 藍牙通不通看這頁

這頁是排查「電腦收不到資料」的主戰場。

```
BLE LINK           115200
──────────────────────────────
PROV Y   TELEM 10Hz
TXF 1234   RXF 12
TXB 28456  RXB 388
ERR 0 CRC 0
```

**標題列右邊:**

| 顯示 | 意思 |
|---|---|
| `115200` | **目前 USART2 鮑率**(和 BLE 模組溝通的速度)。要和模組設定一致才通得了 |

**內容:**

| 顯示 | 全稱 | 意思 |
|---|---|---|
| `PROV Y` | Provisioned | BLE 模組鮑率**已自動對齊**(Y=是/N=否)。N 代表沒佈建成功,查第 6 節 |
| `TELEM 10Hz` | Telemetry | 遙測頻率(和儀表板 TX 同一個) |
| `TXF 1234` | TX Frames | **送出的封包數**(一個一個完整的資料包) |
| `RXF 12` | RX Frames | **收到的封包數**(電腦下的命令) |
| `TXB 28456` | TX Bytes | 送出的**原始位元組數** |
| `RXB 388` | RX Bytes | 收到的**原始位元組數** |
| `ERR 0` | Errors | UART **硬體錯誤數**——正常 0 |
| `CRC 0` | CRC errors | **資料校驗錯誤數**——正常 0;一直漲代表資料損壞 |
| `BRG`（最後可能出現） | Bridge | 目前在**橋接模式**(用 CLI 直通 BLE 模組時) |

**怎麼用這頁判斷藍牙問題(重要):**

| 現象 | 代表什麼 |
|---|---|
| `TXB` 一直漲、電腦卻收不到 | 資料有送出,卡在模組——看 `PROV` 和 `115200` 鮑率對不對 |
| `RXB` 漲但 `RXF` 不動 | 收到的是亂碼(鮑率不合/雜訊),配合 `CRC` 一起看 |
| `PROV N` | 模組還沒佈建成功——重開機或用 CLI `ble auto`,且佈建當下模組不能被手機/電腦連著 |
| `PROV Y` + `115200` | 端點鮑率已對齊,問題不在鮑率了 |
| `ERR`/`CRC` 一直暴增 | 訊號品質差——查接線、上拉電阻,或降鮑率 |

## 5. 原始值頁（RAW）— 看感測器最底層的數字

給進階觀察用。這裡是 MPU6050 還沒經過任何運算的**生資料**。

```
RAW SENSOR
──────────────────────────────
A    120   -34  8192
G     -5    12    -3
T 26.53C
INT 15230
SMP 45120
```

| 顯示 | 全稱 | 意思 | 說明 |
|---|---|---|---|
| `A 120 -34 8192` | Accel | **加速度計**三軸原始值(X Y Z) | 整數 -32768~32767。平放靜止時,朝下那軸約 +8192(=1個重力) |
| `G -5 12 -3` | Gyro | **陀螺儀**三軸原始值(X Y Z) | 靜止時應該接近 0(校正過的話);轉動時才變大 |
| `T 26.53C` | Temperature | **晶片溫度**(攝氏) | MPU6050 內建溫度計,約室溫或略高 |
| `INT 15230` | Interrupt | **MPU 中斷觸發次數** | 每次感測器有新資料就 +1,用來觀察 EXTI 中斷有沒有在跳 |
| `SMP 45120` | Samples | **累計取樣次數** | 姿態解算跑了幾次,持續增加代表 IMU 在正常工作 |

**怎麼用:** 把裝置放桌上不動,`G`(陀螺)三個數字應該都很接近 0。如果不是,
代表需要校正(校正後零偏會存進 BIAS,見第 3 節)。轉動裝置時 `G` 應該明顯變化。

## 6. 系統頁（SYS）— 一眼看全機健康

```
SYSTEM              v1.1.0
──────────────────────────────
UP  01:23:45  CPU 12%
BOOT 17  RST POR
EEP w5 f0
IMU+ EEP+ OLED+
```

| 顯示 | 全稱 | 意思 |
|---|---|---|
| `v1.1.0` | Version | 韌體版本 |
| `UP 01:23:45` | Uptime | **開機到現在的運行時間**(時:分:秒) |
| `CPU 12%` | CPU usage | **處理器忙碌程度**——正常個位數到一二十趴;飆高代表有任務卡住 |
| `BOOT 17` | Boot count | 開機次數 |
| `RST POR` | Reset cause | **上次為什麼重置**(見下方對照表)——最重要的除錯線索之一 |
| `EEP w5 f0` | EEPROM writes/fails | 記憶體寫入成功/失敗次數 |
| 最後一行 | Health | **三個關鍵零件的健康狀態** |

**RST(重置原因)對照:**

| 顯示 | 意思 |
|---|---|
| `POR` | Power-On Reset——**正常上電開機** |
| `PIN` | 外部 NRST 腳位觸發(按了重置鍵) |
| `SOFT` | 軟體主動重置(例如 CLI `reboot`) |
| `IWDG` | **看門狗重置!**——代表有任務卡死超過約 4 秒,系統自救重開了。**看到這個要查哪個任務出問題** |
| `WWDG` / `LPWR` | 視窗看門狗 / 低功耗喚醒(本專案少見) |

**健康狀態(最後一行):** `+` 代表正常、`-` 代表故障

| 顯示 | 意思 |
|---|---|
| `IMU+` / `IMU-` | MPU6050 姿態感測器 正常/離線 |
| `EEP+` / `EEP-` | AT24 記憶體 正常/離線 |
| `OLED+` / `OLED-` | 顯示器本身 正常/異常 |

> 全部 `+` = 三大件都健在。任何一個變 `-`,就去對應的頁面查細節。
> 另外板子上的 **LED 也會說話**:每秒閃一下短亮=正常心跳;快速閃(每秒5下)=
> 有零件故障進入降級模式。

## 7. 會跳出來的提示框（Toast）

這些不是固定頁面,是「剛發生某事」的即時通知,顯示約 1.5 秒:

| 提示 | 什麼時候出現 |
|---|---|
| `CAL OK` / `CAL FAILED` | 陀螺儀校正成功 / 失敗(校正時裝置要靜止不動) |
| `CAL: HOLD STILL` | 校正開始,叫你把裝置拿穩別動 |
| `CLICKS RESET` | 點擊數被歸零(KEY0 長按,或電腦下命令) |
| `TELEMETRY ON` / `OFF` | 遙測開關被切換(KEY1 雙擊) |
| `AIR MOUSE ON` / `OFF` | 空中滑鼠模式切換(KEY0 雙擊) |
| `CHECKPOINT` | (內部事件,一般用不到) |
| `BLE 9600>115200` | BLE 模組鮑率被自動改好了(開機自動佈建成功) |
| `IMU OFFLINE` | 想校正但感測器沒連上 |

## 8. 診斷測試圖（OLED TEST）

如果你的螢幕顯示怪怪的(錯位、滾動、邊緣被切),用序列埠 CLI 輸入 `oled test`
會顯示一張測試圖:外框 + 十字線 + 左右兩排 0~7 的數字。

- **外框四邊都完整看得到** = 內縮設定正確、畫面沒被切
- **外框某邊看不到** = 邊緣被模組外框遮住,用 `oled inset` 微調
- **畫面錯位/滾動** = 面板晶片是 SH1106 之類的變體,用 `oled ctrl sh1106` 切換

詳細流程見 README 的「OLED 顯示異常診斷流程」。

## 快速索引:我看到 ___ 該去哪查?

| 我想知道 | 看哪頁 |
|---|---|
| 裝置現在朝哪個方向 | 儀表板(DASH)的 R/P/Y |
| 點擊數對不對、有沒有存進去 | EEPROM(STOR),看 CLK 和 `*` |
| 電腦收不到藍牙資料 | BLE鏈路(COMM),看 PROV/鮑率/TXB/CRC |
| 感測器是不是真的在動 | 原始值(RAW),看 G 和 SMP |
| 剛剛為什麼重開機 | 系統(SYS)的 RST |
| 哪個零件壞了 | 系統(SYS)最後一行的 +/- |
| 板子跑的是不是新韌體 | 開機畫面或系統頁的 v1.1.0 |
